Hizmetler

OS Hizmetleri

İşletim sistemi iki ana gruba ayrılan hizmetler sunar:

Kullanıcıya Yönelik Hizmetler
  • Kullanıcı Arayüzü (UI): CLI, GUI ve dokunmatik arayüz seçenekleri.
  • Program Yürütme: Programı belleğe yükler, çalıştırır ve normal/anormal bitişi yönetir.
  • I/O Operasyonları: Çalışan program dosya veya cihaz üzerinde I/O gerektirebilir; OS bunu güvenli yönetir.
  • Dosya Yönetimi: Okuma, yazma, oluşturma, silme, arama, listeleme ve izin yönetimi.
  • İletişim: Süreçler arası aynı/farklı bilgisayarda mesaj iletimi — shared memory veya message passing ile.
  • Hata Tespiti: CPU, bellek, I/O veya kullanıcı programlarındaki hataları tespit edip düzeltici aksiyon alır.
Sistem Verimliliği Hizmetleri
  • Kaynak Tahsisi: CPU döngüsü, bellek, dosya depolama ve I/O aygıtlarını süreçler arasında yönetir.
  • Accounting (Muhasebe): Kullanıcıların kaynaklarını ne kadar ve ne tür kullandığını izler.
  • Koruma ve Güvenlik: Bilgilere erişimi denetler; sistem kaynaklarına yetkisiz erişimi engeller.
Arayüz

Kullanıcı Arayüzleri

Command-Line Interface (CLI)

Kullanıcı komutları doğrudan metin olarak girer. Command interpreter (kabuk/shell) bu komutları alıp çalıştırır.

Shell Türleri
bash, sh, csh, ksh, zsh gibi UNIX/Linux kabukları. Windows'ta cmd.exe ve PowerShell.
Kernel vs Sistem Programı
Bazı komutlar (cd, exit) shell'in içindedir. Diğerleri (ls, cp) ayrı sistem programlarıdır — shell onları çağırır.
Esneklik
Betik (script) yazımı, pipe, yönlendirme ve otomasyon için güçlü araçtır. Sunucu yönetiminde vazgeçilmez.

Graphical User Interface (GUI)

Masaüstü metaforu: simgeler, pencereler, menüler ve fare ile etkileşim. İlk olarak Xerox PARC'da icat edildi; Apple Lisa ve Mac ile yaygınlaştı.

Windows
Microsoft Windows — başlat menüsü, görev çubuğu. GUI her yerden erişilebilir.
Mac OS X Aqua
Apple'ın Aqua arayüzü — Dock, Finder; Mach kernel ve BSD UNIX üzerine inşa.
Linux Desktop
GNOME, KDE gibi ortamlar; CLI ve GUI bir arada kullanılabilir.

Touchscreen Arayüzü

Mobil cihazlar için klavye+fare yerine dokunmatik etkileşim. iOS ve Android bu modeli benimsemiştir.

Gesture (Hareket)
Kaydırma, sıkıştırma, çift tıklama, döndürme gibi dokunmatik hareketler.
Sanal Klavye
Fiziksel klavye olmaksızın ekran üzerinde metin girişi sağlar.
Ses Komutları
Siri, Google Assistant gibi yapay zeka destekli sesli etkileşim.
API

System Calls

💡

System Call Nedir?

System call, OS tarafından sağlanan hizmetlere programlama arayüzüdür. Genellikle C/C++ ile yazılır. Programlar doğrudan system call yerine yüksek seviyeli API'leri kullanır.

Win32 API
Windows uygulamaları için standart API. CreateProcess(), ReadFile(), WriteFile() gibi fonksiyonlar system call'ları saralar.
POSIX API
UNIX, Linux ve Mac OS X için taşınabilir standart. fork(), open(), read(), write(), exit() içerir.
Java API (JVM)
Java Virtual Machine üzerinden işletim sistemi bağımsız çalışır; JVM altında native system call'lara çevrilir.

Mimari

OS Yapı Modelleri

1. Basit / Monolithic (MS-DOS)
Modüler değil; OS ve uygulama arasında zayıf ayrım. En az alan için en fazla işlevsellik. Güvenlik açısından tehlikeli — kötü program sistemi çökertebilir. Örnek: MS-DOS, eski Unix
2. Katmanlı Yapı (Layered)
OS katmanlara bölünür; her katman yalnızca bir alt katmanı kullanır. Hata ayıklama kolaylaşır; katmandan katmana geçişte performans maliyeti oluşur. THE OS, Venus
3. Microkernel (Mach)
Kernel minimum tutulur; dosya sistemi, aygıt sürücüleri vb. user space'e taşınır. Güvenli ve taşınabilir; ancak user space–kernel space arası IPC mesajlaşması performans yükü oluşturur. Mach, QNX, MINIX
4. Modüller / LKM
Çalışma zamanında yüklenebilir/kaldırılabilir kernel modülleri (Loadable Kernel Modules). Monolithic kernel'in esnekliği ve microkernel'in modülerliğini birleştirir. Linux, Solaris
5. Hibrit (Hybrid)
Birden fazla yaklaşımı birleştirir:
  • Linux: Monolithic + LKM modülleri
  • Windows: Monolithic + microkernel unsurları
  • Mac OS X: Mach microkernel + BSD UNIX katmanı
🔑

Policy vs Mechanism Ayrımı

  • Policy (Politika — Ne yapılacak?): CPU'nun hangi sürece ne zaman verileceği kararı.
  • Mechanism (Mekanizma — Nasıl yapılacak?): CPU'yu süreçler arasında geçirme tekniği (timer, context switch).
  • Ayrım esneklik sağlar: politika değişse bile mekanizma değişmez. Maksimum uyarlanabilirlik.
Başlatma

Boot Süreci

Bilgisayara güç verildiğinde OS yüklenmeden önce gerçekleşen adım adım süreç:

1. Power-On (Güç Açılışı)
CPU, sabit bir bellek konumunda (reset vector) çalışmaya başlar. Donanım bileşenleri sıfırlanır.
2. Firmware / ROM (BIOS / UEFI)
ROM'daki firmware çalışır; POST (Power-On Self Test) ile donanım kontrolü yapar. Boot aygıtını belirler.
3. Bootstrap Loader (GRUB)
Diske gider, OS kernel'ini bulur ve belleğe yükler. GRUB (Grand Unified Bootloader) birden fazla işletim sistemi seçimi sunar.
4. Kernel Başlatma
Kernel kontrolü alır; donanım tespiti, driver yükleme, bellek yönetimi başlatma. Sistem kaynaklarını hazırlar.
5. Init / Systemd
İlk kullanıcı süreci (PID 1) başlar. Tüm sistem servisleri ve daemon'lar bu süreçten türetilir. Kullanıcı oturumu hazırlanır.

System call nedir ve API ile farkı nedir?
Tıkla → cevabı gör
System call, OS hizmetlerine programlama arayüzüdür. API (Win32, POSIX, Java), system call'ların üstündeki yüksek seviyeli sarmalayıcıdır; programlar API'yi kullanır, doğrudan system call'ı genellikle kullanmaz.
