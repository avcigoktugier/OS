Race Condition

🚨

counter++ Tek Komut Değildir!

counter++ üç makine komutuna karşılık gelir:

  1. register = counter — değeri register'a yükle
  2. register = register + 1 — register'ı artır
  3. counter = register — geri yaz

İki süreç aynı anda çalışırsa: counter=5 iken sonuç 4 veya 6 olabilir!

Interleaving Örneği (counter = 5)
AdımProducer (counter++)Consumer (counter--)counter
S0reg_P = counter → 55
S1reg_P = reg_P + 1 → 65
S2reg_C = counter → 55
S3reg_C = reg_C - 1 → 45
S4counter = reg_P → yazıldı6
S5counter = reg_C → yazıldı4 ← YANLIŞ!
Çözüm Koşulları

Kritik Bölge Problemi

Kritik bölge (critical section), paylaşılan değişkene erişilen kod parçasıdır. Geçerli bir çözüm 3 koşulu sağlamalıdır:

🔒

1. Mutual Exclusion

Bir süreç kritik bölgedeyken, başka hiçbir süreç kritik bölgesine giremez. Temel güvenlik koşulu.

▶️

2. Progress (İlerleme)

Kritik bölge boşsa ve girmek isteyen süreç varsa, bu seçim sonsuza kadar ertelenebilmez. Starvation'a yol açmaz.

⏰

3. Bounded Waiting

Sınırlı bekleme: bir süreç kritik bölgeye girmek için sonsuz bekleyemez. Belirli bir sınır içinde sırası gelmelidir.

Yazılım Çözümü

Peterson'ın Çözümü

💡

İki Süreç için Yazılım Tabanlı Çözüm

turn ve flag[] değişkenleri kullanır. Tüm 3 koşulu sağlar, ancak modern işlemcilerde instruction reordering sorunu yaşanabilir.

// Process Pi (i=0 veya 1; j = karşı taraf)
do {
    flag[i] = true;           // Hazırım: girmek istiyorum
    turn = j;                 // Önce j'ye fırsat ver (kibarlık)
    while (flag[j] && turn == j)
        ; // Meşgulse bekle (busy-wait)

    // ——— Kritik Bölge ———
    // Paylaşılan kaynağa güvenli erişim

    flag[i] = false;          // Çıkış: artık burada değilim

    // ——— Geri Kalan Bölge ———
} while (true);
flag[i] = true
Süreç i'nin kritik bölgeye girmek istediğini bildirir.
turn = j
Çakışma durumunda diğer sürece öncelik verir; deadlock ve starvation önler.
Modern Sorun
Modern derleyici ve CPU'lar bağımsız komutların sırasını değiştirebilir (instruction reordering / memory reordering). Memory barrier gerektirir.
Donanım

Donanım Tabanlı Çözümler

Interrupt Masking
Uniprocessor'da interrupt'ları devre dışı bırak. Kritik bölge boyunca context switch engellenir. Çok işlemcili sistemlerde yetersiz — diğer CPU'yu etkilemez.
test_and_set()
Atomik operasyon: kilidi okur ve true set eder. Spinlock (döngüsel kilit) yapımında kullanılır. Bounded waiting garanti etmez.
compare_and_swap() (CAS)
Beklenen değerle eşleşirse değiştirir — atomik. Daha güçlü: birden fazla sonuç durumu. Modern CPU'larda doğrudan desteklenir (x86: CMPXCHG).
Atomic Variables
Sayaçlar için atomik increment/decrement. Java'da AtomicInteger, C'de _Atomic. Lock-free basit işlemler için yeterli.
Kilit

Mutex Lock

En basit senkronizasyon aracı. acquire() ve release() atomik operasyonlardır.

// Kullanım kalıbı
mutex_lock.acquire();
    // ——— Kritik Bölge ———
mutex_lock.release();
🔄

Spinlock — Busy-Wait

Mutex beklerken süreç döngüde döner (CPU zaman harcar). Kısa bekleme için verimli — context switch maliyetinden düşük. Uzun bekleme için semaphore tercih edilir.

Semafor

Semaphore

Semaphore, bir tam sayı değişkenidir. Yalnızca iki atomik operasyonla erişilir:

wait(S) / P(S)
S > 0 ise S'i azalt ve devam et. S = 0 ise süreç bekleme kuyruğuna alınır (CPU serbest bırakılır).
signal(S) / V(S)
S'i artır. Bekleme kuyruğunda süreç varsa birini uyandırır (ready queue'ya taşır).
Binary Semaphore (Mutex)
S değeri yalnızca 0 veya 1. Mutex lock gibi davranır; mutual exclusion sağlar.
Counting Semaphore
S değeri 0'dan N'e. N adet kaynağın yönetimi için. Örnek: 3 yazıcı, S=3 ile başlatılır.
Semaphore Simülasyonu
3
Mevcut değer (N=3 olarak başlatıldı)
⛔

Semaphore Kullanım Hataları

  • signal() → wait() sırası (yanlış sıra): mutual exclusion ihlali — ikisi birden kritik bölgede.
  • wait() → wait() sırası (iki kez wait): deadlock — kimse ilerleyemez.
  • wait() veya signal() unutulursa: starvation veya deadlock oluşur.
Klasik

Klasik Senkronizasyon Problemleri

Üretici-Tüketici (Bounded-Buffer)

N boyutlu dairesel buffer; üretici ekler, tüketici çıkarır. Eş zamanlı erişimi senkronize etmek gerekir.

mutex = 1
Buffer'a eşzamanlı erişimi engeller (binary semaphore).
full = 0
Dolu slot sayısı. Tüketici wait(full) ile bekler.
empty = N
Boş slot sayısı. Üretici wait(empty) ile bekler.
// Üretici
wait(empty); wait(mutex);
  buffer[in] = item; in = (in+1) % N;
signal(mutex); signal(full);

// Tüketici
wait(full); wait(mutex);
  item = buffer[out]; out = (out+1) % N;
signal(mutex); signal(empty);

Readers-Writers Problemi

Bir veri kümesini birden fazla okuyucu aynı anda okuyabilir; fakat yazar münhasır erişim ister.

İlk Okuyucu-Yazar
Okuyucu beklemez; yazar starvation'a uğrayabilir.
İkinci Okuyucu-Yazar
Yazar hazırsa yeni okuyucu bekler; okuyucu starvation riski.
Semaforlar
mutex (read_count koruması) + rw_mutex (yazar münhasırlığı) + read_count sayacı.
⚠️

Starvation Riski

Her iki çözümde de bir taraf starvation'a uğrayabilir. Adil çözüm için readers-writers lock (RWLock) kullanılır.

Dining Philosophers (Yemek Yiyen Filozoflar)

5 filozof, 5 çubuk, yuvarlak masa. Her filozofun yiyebilmesi için iki çubuğa ihtiyacı var. Klasik deadlock ve starvation örneği.

Naif Çözümün Sorunu
Herkes sol çubuğu alırsa: deadlock (dairesel bekleme). Herkes aynı anda aç olursa: starvation.
Çözüm 1: Maksimum 4 Oturur
En az bir filozofun iki çubuğu da alması garanti — deadlock önlenir.
Çözüm 2: Her İkisi Müsaitken Al
Tek atomik işlemde her iki çubuğu birden al (mutex ile korunur).
Çözüm 3: Asimetrik Sıra
Tek numaralı filozoflar önce sol, çift numaralılar önce sağ çubuğu alır. Dairesel bekleme kırılır.
Yüksek Seviye

Monitor

🏗️

Monitor Nedir?

Yüksek seviyeli soyutlama. Aynı anda yalnızca bir süreç monitörde aktif olabilir. Mutual exclusion otomatik sağlanır — programcı wait/signal sırasını yönetmek zorunda değildir.

Condition Variable (x)
Monitor içinde bekleme için: x.wait() — signal gelene kadar süreci askıya alır. x.signal() — askıdaki bir süreci uyandırır (kimse yoksa etkisizdir).
Java synchronized
Java'da synchronized anahtar kelimesi monitor semantiği sağlar. wait(), notify(), notifyAll() condition variable işlemleri.
Semaphore ile Farkı
Monitor'de mutual exclusion derleyici garantisiyle otomatik. Semaphore'da wait/signal sırasını programcı yönetir — hata riski yüksek.
Kilitlenme

Deadlock (Kilitlenme)

🔴

Deadlock için 4 Koşul — Hepsi Aynı Anda Olmalı

  1. Mutual Exclusion: Kaynak aynı anda yalnızca tek süreç tarafından tutulabilir.
  2. Hold and Wait: Süreç, elindeki kaynağı tutarken başka kaynak bekler.
  3. No Preemption: Kaynak yalnızca sürecin kendisi gönüllü bırakır; dışarıdan alınamaz.
  4. Circular Wait: P0 → P1 → ... → Pn → P0 şeklinde döngüsel bekleme zinciri.

Deadlock Yönetim Yöntemleri

Yöntem Fikir Örnek / Not
Prevention (Önleme) 4 koşuldan birini ortadan kaldır Kaynakları önceden toplu al; kaynak sıralaması
Avoidance (Kaçınma) Güvenli durumda kal Banker's Algorithm; kaynak tahsis grafiği
Detection & Recovery Deadlock oluşunca tespit et, kurtar Bekleme döngüsü tespiti; kaynak geri alma
Ignore (Devekuşu) Deadlock'u görmezden gel UNIX, Linux, Windows — nadir deadlock tolere edilir
🏦

Banker's Algorithm

Güvenli durum: tüm süreçlerin bir çalışma sırası bulunabilir. Kaçınma algoritması: yeni kaynak talebi güvenli durumda kalıyorsa kabul edilir, aksi hâlde reddedilir. Yüksek overhead nedeniyle pratikte nadiren kullanılır.
