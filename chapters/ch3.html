Temel Tanım

Süreç Kavramı

💡

Süreç Nedir?

Süreç (process), yürütme halindeki bir programdır. Program pasif (disk'te), süreç aktiftir (bellekte çalışır).

📄

Program vs Süreç

Program disk'teki pasif varlıktır (binary dosya). Süreç bellekteki aktif varlıktır. Aynı programdan birden fazla süreç çalışabilir (çoklu kullanıcı).

🔢

Sequential Çalışma

Bir adım tamamlanmadan bir sonraki başlamaz. CPU komutları sırayla işler; ancak çoklu süreçle paralel görünüm sağlanır.

⏱️

Batch vs Interactive

Batch sistemlerinde "job" kavramı kullanılır. Timesharing (etkileşimli) sistemlerde ise "task" veya "user process" denir.

Yaşam Döngüsü

Süreç Durumları

Bir süreç yaşamı boyunca 5 farklı durumdan geçer. Duruma tıkla:

New
Ready
Running
Waiting
Terminated
Bir duruma tıkla → açıklama görün

Durum Geçişleri

New → Ready
admitted — OS süreci kabul eder, ready queue'ya alır.
Ready → Running
dispatch — CPU scheduler (kısa-dönem) süreci seçer ve CPU'ya atar.
Running → Waiting
I/O isteği veya olay bekleme — süreç kendisi bekler; CPU'dan gönüllü ayrılır.
Running → Ready
interrupt / preempt — time slice doldu veya yüksek öncelikli süreç hazır; OS CPU'yu geri alır.
Waiting → Ready
I/O tamamlandı / olay gerçekleşti — süreç tekrar çalışmaya hazır.
Running → Terminated
exit() / hata — süreç tamamlandı veya hata ile sonlandırıldı.
Veri Yapısı

Process Control Block (PCB)

📋

PCB Nedir?

Her süreçle ilişkili bilgileri tutan veri yapısı. Task Control Block da denir. OS, süreci yönetmek için PCB'yi kullanır.

Process State
new, ready, running, waiting, terminated — sürecin mevcut durumu.
Program Counter
Süreç için çalışacak sonraki komutun adresi.
CPU Registers
Tüm genel amaçlı register'lar, durum bayrakları (PC ile birlikte context switch'te kaydedilir).
CPU Scheduling Info
Öncelik, scheduling kuyruğu bağlantıları, zamanlama parametreleri.
Memory Management Info
Page table, segment table, bellek sınırları.
Accounting Info
CPU kullanım süresi, zaman sınırları, hesap numarası, job/process numarası.
I/O Status Info
Sürece tahsis edilmiş I/O aygıtları, açık dosyaların listesi.
⚠️

Context Switch = Saf Overhead

Mevcut sürecin PCB'ye kaydedilmesi + yeni sürecin PCB'den yüklenmesi sırasında hiçbir faydalı iş yapılmaz. Saf zaman kaybıdır; donanım desteği (birden fazla register seti) bu yükü azaltır.

🐧

Linux: task_struct

Linux'ta PCB'ye karşılık gelen yapı task_struct'tır. İçerdiği alanlar: pid, state, parent, children, files, mm (memory map).

Zamanlama

Süreç Zamanlama

Short-term Scheduler (CPU Scheduler)
Ready queue'dan süreci seçer ve CPU'ya atar. Milisaniye bazında çalışır — en sık çağrılan scheduler. Hız kritik!
Long-term Scheduler (Job Scheduler)
Hangi süreçlerin ready queue'ya alınacağını seçer. Saniyeler hatta dakikalar bazında çalışır. Multiprogramlama derecesini (bellekteki süreç sayısı) kontrol eder.
Medium-term Scheduler (Swapper)
Süreci bellekten diske taşır (swap out) veya geri alır (swap in). Multiprogramlama derecesini dinamik azaltır/artırır.
📊

I/O-bound vs CPU-bound

  • I/O-bound: Daha fazla I/O bekler, kısa CPU burst'leri. Örnek: metin editörü.
  • CPU-bound: Uzun CPU burst'leri, az I/O. Örnek: video encoder, bilimsel hesaplama.
  • Long-term scheduler: iyi bir karışım seçmeli — tamamen I/O veya CPU-bound olmaz.
fork / exec

Süreç Operasyonları

pid_t pid = fork();      // Yeni süreç oluştur
if (pid == 0) {
    // Çocuk süreç (child)
    execlp("/bin/ls", "ls", NULL);  // Çocukta ls çalıştır
} else if (pid > 0) {
    // Ebeveyn süreç (parent); pid = child'ın PID'i
    wait(NULL);          // Child bitmesini bekle
    printf("Child bitti.\n");
} else {
    // Hata: fork() başarısız, -1 döndü
}
fork()
Mevcut süreci kopyalar (adres alanı, dosyalar vb.). Parent'a child'ın PID'i (>0), child'a 0 döner. Hata durumunda -1.
exec()
Mevcut sürecin adres alanını yeni programla değiştirir. execl(), execlp(), execvp() varyantları. fork() → exec() kalıbı yaygın.
wait()
Parent süreci, child'ın bitmesini bekler. Child'ın exit status'unu toplar. Zombie önler.
exit()
Süreci sonlandırır, kaynakları serbest bırakır. Son kodu (0=başarı, >0=hata) OS'a bildirir.
Zombie Süreç
Child bitti ama parent henüz wait() yapmadı. PCB hâlâ var — exit status beklenirken. Çok sayıda zombie kaynak sızıntısına yol açar.
Orphan Süreç
Parent bitti, child devam ediyor. init/systemd (PID 1) orphan'ları evlat edinir (adopt) ve bekler.
İletişim

Süreçler Arası İletişim (IPC)

📦 Shared Memory

  • Ortak bellek bölgesi paylaşılır
  • Kullanıcı süreci kontrolünde
  • Çok hızlı — OS müdahalesi az
  • Senkronizasyon programcıya bırakılır
  • Race condition riski yüksek

✉️ Message Passing

  • OS aracılık eder
  • send() / receive() ile haberleşme
  • Dağıtık sistemler için uygun
  • Daha yavaş (sistem çağrısı gerekir)
  • Senkronizasyon OS tarafından
